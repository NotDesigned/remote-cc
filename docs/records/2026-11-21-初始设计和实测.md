# 2026-11-21 初始设计和实测

> 读者：维护者

状态：存档，写成后不再修改。对应版本：0.1.0 之前的初始设计到 0.1.0。内容整理自当时的 `docs/DESIGN.md`；当前设计见 [docs/architecture.md](../architecture.md)。

## 目标

在没有安装 Claude Code 的电脑上运行 remote-cc，经 ssh 使用服务器上的 Claude Code，而 Claude Code 的所有文件读写和命令执行都落在电脑上。

## 当时比较过的方案

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| 自定义 MCP 服务器代理全部工具，再用 `--disallowedTools` 禁用内置工具 | 服务器上不需要 FUSE | 丢掉内置 Edit、Read 的语义和 diff 界面 |
| 只把 `SHELL` 或 `CLAUDE_CODE_SHELL` 指向包装脚本 | 简单 | 要冒充完整的 bash（快照生成等），文件工具照样落在服务器上 |
| 电脑正向 sshfs 挂载服务器，在服务器上开发 | 无 | 和需求相反：代码和运行环境都在服务器上 |

当时还考虑过挂载路径不可写时的降级办法（用户命名空间里的非特权 FUSE，或挂到缓存目录再做 cwd 前缀替换），以及用 PreToolUse hook 把 Grep、Glob 改为在电脑上运行 `rg`。这些都没有实现。

## 当时的开发计划

- 第一步，命令通道：`rcc serve` 加 `rcc-shim`，手工设置 `ssh -R` 和 `CLAUDE_CODE_SHELL_PREFIX`，验证 Bash 工具在电脑上执行、cwd 追踪、退出码、Ctrl-C。完成。
- 第二步，文件通道：内置 SFTP 服务加 `sshfs -o slave` 同路径挂载，验证 Read、Edit、Write、Glob、Grep。完成。
- 第三步，一条命令启动：上传 shim、建连接、挂载、起终端跑 claude、退出时清理。完成。
- 第四步，增强：断线保持会话、非 root 时用用户命名空间挂载、Grep 和 Glob 改在电脑上执行、断线重连、MCP 降级模式、在真实的 Windows 和 macOS 电脑上验证。当时未完成；其中 Windows 和 macOS 的电脑一侧后来进了 CI。

## 实测记录（服务器 Ubuntu 24.04，Claude Code 2.1.330）

- Claude Code 拼命令的方式是 `[...setupParts, "eval <命令>", "pwd -P >| <cwd 文件>"].join(" && ")`，设置了前缀时整串作为一个参数交给前缀程序，最终执行 `bash -c -l "'rcc-shim' '<整串命令>'"`。shim 收到的 argv 只有一项。
- 整串命令里有：加载服务器 shell 快照的 `source`（在电脑上应该丢掉）、若干 `export`（原样带过去即可）、`eval '<用户命令>'`、写 cwd 文件的 `pwd -P`（Claude 靠它追踪 cd，所以文件要写在服务器上）。
- cwd 文件路径在不需要引号时是裸路径，例如 `/tmp/claude-b614-cwd`。Claude 只接受工作目录范围内的 cwd 变化，同路径挂载正好满足。
- shell 快照的生成不经过前缀，所以 shim 只处理真正的命令。
- 非登录 ssh 会话的 PATH 里没有 `~/.local/bin`，所以探测阶段要主动查找 claude 的绝对路径。
- 以 root 运行时 Claude Code 不允许 `--dangerously-skip-permissions`，除非设置了 `IS_SANDBOX=1`。这个变量还有其他小影响：遇到 529 过载会一直重试、会话来源标记为 `is_sandbox`、少数功能被关闭。实测：默认可以用 skip-permissions，命令在电脑上执行；加 `--no-is-sandbox` 后被拒绝。
- 端到端：真实的 `ssh -R`（服务器上的 unix socket 到电脑上的 TCP 端口）加 `claude -p`：环境变量取的是电脑的，`cd` 在后续调用里保持，退出码正确透传。
- 一条命令启动：remote-cc 跑在独立的挂载命名空间里，让两边在同一路径下看到不同的目录，结果 Read 读到电脑的内容，Edit、Write 写到电脑的磁盘，Bash 在电脑上执行，服务器的真实目录没有变化。交互界面用伪终端驱动测试，`/exit` 后退出码为 0，收到 SIGTERM 时也能完整清理。
- SFTP 服务：读写、3MB 文件往返、`mv -f`、truncate、chmod、utimes、`df`，以及在挂载点里 `git init`、`git commit` 后在电脑上 `git fsck`。
- 历史档案：两个历史档案、相同路径跑三次。第一台让 Claude 记住一个暗号；第二台执行 `--continue` 没有接上第一台的对话；第一台执行 `--continue` 正确答出暗号。服务器原本的 `projects/` 没有新增内容。
- 追加的系统提示词：Claude 能正确回答命令在哪台电脑执行，也知道项目目录外的 Read 读的是服务器上的文件；用户自己传的追加提示词同时生效。
- 多个 Claude 账号：设置 `CLAUDE_CONFIG_DIR` 后，`.claude.json` 和 `.credentials.json` 都放进这个目录；指向空目录时 `auth status` 显示 `loggedIn: false`，默认账号不受影响。`auth status` 对令牌只检查是否配置，不检查是否有效。真实账号的浏览器授权当时没有测。
- 进程清理：Unix 上用 `kill -9` 结束 remote-cc，电脑上的后台命令、看门狗和临时目录全部被清理，服务器上的 sshfs 和 claude 也结束了。Windows 上的 Job Object 当时只验证到交叉编译通过。
