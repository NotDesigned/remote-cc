# 2026-11-24 服务端和多用户的实测

> 读者：维护者

状态：存档，写成后不再修改。对应版本：0.2.0 到 0.5.3（2026-11-22 至 2026-11-24）。内容整理自当时的 `docs/DESIGN.md` 和提交说明；当前设计见 [docs/architecture.md](../architecture.md)。

## 服务端容器化（0.2.0）

- 起因：Claude 以 root 直接运行在服务器上，项目外的 Read、Write、WebFetch、MCP 都作用于宿主机。改用专用用户也不行：那台 Ubuntu 24.04 设置了 `apparmor_restrict_unprivileged_userns=1`，普通用户不能创建挂载命名空间。
- 用户容器的 sshd：`-R` unix socket 可用，`-R` TCP 端口被拒绝，`-L` 在实际使用时被拒绝（administratively prohibited）。
- 两边是同一台机器、用本地构建的镜像、容器只监听 127.0.0.1：部署完成、`known_hosts` 写入，开启主机密钥校验后连接成功；在容器里经挂载读写了电脑上的文件，经 shim 在电脑上执行了命令；会话结束后容器里没有残留。容器里的 claude 当时还没登录，会话部分用假的 claude 测试。
- 在服务器上本地构建镜像临时产生约 2GB 的构建缓存，一度把磁盘写满，之后镜像改由 CI 构建。

## 经 sudo 账号部署（0.2.1）

用两个临时用户测试：免密 sudo，以及需要密码时未提供、错误、正确三种情况都符合预期，密码没有出现在进程列表和日志里。

## 每台电脑一个 Claude 账号、shim 按内容寻址（0.3.0）

- 两台模拟的电脑同时连同一个容器、用同一个项目路径：账号目录、历史、命令执行都各自正确。
- 并发测试发现两个问题：两台电脑同时首次连接时，上传 shim 共用一个临时文件名，其中一个改名失败；不同版本的 remote-cc 互相覆盖服务器上唯一的 shim。改为按内容寻址、上传用会话独有的临时文件名。
- 更新服务器测了五种情况：无变化、镜像有更新、只改注释、有活跃会话被拒绝、`--force`。
- 有用户的 PATH 里有 Anaconda 或 Qt 的 `rcc.exe`，按提示执行 `rcc …` 时运行的是那个程序。之后提示一律使用实际调用的程序名，默认命令名改为 `remote-cc`。

## IPv6（0.3.2）

端口映射原来写成 `0.0.0.0:PORT:22`，Docker 遇到显式的 `0.0.0.0` 只绑定 IPv4，只能用 IPv6 访问服务器的客户端连接被拒绝（Windows 报 10061）。改为不写宿主机地址。实测：新部署同时监听两种协议，`ssh -6 root@::1` 能连通；旧部署更新后也能连通；`--bind 127.0.0.1` 仍然只监听回环地址。

## 多用户服务器（0.4.0）

- 在一次性的测试实例上：每个服务器用户只能到达自己的容器；经网关跳到别人的容器或宿主机被拒绝（administratively prohibited）；别人的公钥被容器拒绝；网关上不能拿到 shell、TTY，不能做反向转发；经网关完成一次完整会话；删除用户立即撤销访问；`--purge` 删除数据。
- 测试中发现：一次性密钥的转发权限原本写在网关和容器共用的那个文件里，在容器里也生效，持有者可以在登记前往用户的容器里放一个 `-R` socket。于是把邀请码拆成两半。
- 邀请码：重复使用、过期、滥用（shell、TTY、`-R`、`-L`、跳到别的容器、注入密钥选项、多行夹带）都被拒绝，且不消耗邀请码。
- 迁移：拒绝、回滚和成功（数据、登录、主机密钥保留）三种情况。

## git 在电脑上执行（0.5.1）

- 服务端镜像原来没有 git，Claude Code 自己调用的 git 在服务器上全部失败，`--worktree` 不可用。
- 本地实测（真实 Claude Code 2.1.325 加一个假的 Messages API）：`-w wt1` 时 Claude 发出约 20 次 git 调用，全部到了电脑上；worktree 建在 `<项目>/.claude/worktrees/wt1`，分支 `worktree-wt1`，Bash 命令在 worktree 里执行。
- CI 里发现：git 在电脑上建好 worktree 后，Claude 在容器里立刻 `realpath` 却得到 ENOENT，原因是 `negative_timeout=1` 让内核把「不存在」缓存了 1 秒。改为 0。
- 当时还把 sshfs 自己的目录缓存也关掉了，结果明显变慢：没有目录缓存时每个文件都要单独 LSTAT 一次，一个上千文件的目录就是上千次往返。0.5.3 恢复目录缓存，时间从默认的 20 秒缩短为 5 秒。
- 有用户报告 Windows 上每条命令都是退出码 1 且没有输出。之后启动前先在电脑的 shell 里试跑一条命令。
